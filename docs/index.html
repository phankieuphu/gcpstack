Open source · Written in Go · Project plan

Your whole Google Cloud, on localhost.

GCPStack is one binary that emulates Cloud Storage, Pub/Sub, Secret Manager and more. One port, one config file, and services that talk to each other. Like LocalStack, but for GCP.

The problem

Many emulators. No single tool.

GCP developers run a separate emulator for each service. Each has its own start command, port and setup, and wiring them together is your job.

Pub/Sub emulator
Official, from the gcloud SDK. Its own process and port.
Firestore / Datastore emulator
Official. Another process, another port.
fake-gcs-server
Community project for Cloud Storage, written in Go.
bigquery-emulator
Community project for BigQuery, also in Go.
GCPStack: one process, one port, one event bus.
Start everything with one command. Configure everything in one file.
:4510
What it does

Built for the way you actually test.

01
One binary, one port
gRPC and REST share port 4510. The gateway routes each request by its content type.
02
Services that work together
Storage events go to Pub/Sub. Push subscriptions call your HTTP handler. Scheduler publishes to topics.
03
Real APIs, from protos
Servers are generated from Google's official googleapis definitions. Methods not built yet return Unimplemented, never a fake success.
04
Works with official SDKs
Go, Java, Python and Node clients connect through the standard emulator variables or a custom endpoint. No code changes.
05
Terraform-ready
Point the Google provider's custom endpoints at localhost and test your infra code without a cloud account.
06
Seed, persist, reset
Create resources from a YAML file. Keep state in memory or in SQLite. Reset everything with one call between tests.

The service contract

Every service is a plugin. It registers its own gRPC and HTTP handlers, listens to the bus, and knows how to reset itself. Users can turn services on or off with SERVICES=storage,pubsub.

type Service interface {
    Name() string
    RegisterGRPC(s *grpc.Server)
    RegisterHTTP(mux *http.ServeMux)
    Subscribe(bus *eventbus.Bus)
    Reset(ctx context.Context) error
}

Quickstart (planned)

Three steps. Your code stays the same.

1. Describe your resources
# init.yaml
project: demo-project
services: [storage, pubsub]
storage:
  buckets:
    - name: uploads
      notifications:
        - topic: file-events
pubsub:
  topics:
    - name: file-events
      subscriptions:
        - name: file-worker
          push: http://host.docker.internal:8080/hooks/files
2. Start GCPStack
docker run -p 4510:4510 \
  -v ./init.yaml:/etc/gcpstack/init.yaml \
  ghcr.io/phankieuphu/gcpstack
3. Point your SDK at it
export STORAGE_EMULATOR_HOST=http://localhost:4510
export PUBSUB_EMULATOR_HOST=localhost:4510

// Go: no changes to your code
client, _ := pubsub.NewClient(ctx, "demo-project")
Tech stack

Boring tools, on purpose.

Go grpc-go googleapis protos (genproto) net/http + h2c cmux SQLite (modernc, no cgo) slog Prometheus Docker testcontainers-go

Design principles

Match reality
Same request shapes, same gRPC status codes, same error messages as GCP.
Be honest about gaps
A coverage table in the README. Unsupported methods fail loudly.
Test like a user
Integration tests use the official client libraries, and the same suite can run against real GCP behind a flag.

│   ├── eventbus/        in-process pub/sub
│   ├── store/           memory, sqlite
│   ├── resname/         projects/{p}/... parser
│   ├── config/          env + init.yaml
│   └── admin/           health, reset, UI
├── test/integration/    official SDK tests
├── examples/terraform/
└── Dockerfile
